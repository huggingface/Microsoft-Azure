# Enable and disable reasoning

Some models can answer directly or generate a reasoning trace before the final answer. You choose the mode per request, so you can switch without redeploying the model.

Reasoning can improve planning, coding, and other multi-step tasks, but it also adds latency and output tokens. Defaults and supported controls vary by model, so check the model page before relying on a particular setting.

## Chat Completions API

Send Chat Completions requests to `/openai/v1/chat/completions`. Reasoning switches are extensions understood by the serving engine and the model's chat template; they are not standard Chat Completions fields.

With cURL, place `chat_template_kwargs` directly in the JSON body. With the Python SDK, pass it through `extra_body` so the SDK forwards it as a top-level request field.

### vLLM

This example enables reasoning with `enable_thinking`. Set it to `false` to request a direct answer from models that support both modes.

<hfoptions id="vllm-client">
<hfoption id="cURL">

```bash
curl -sS -X POST \
  "https://<ACCOUNT_NAME>.services.ai.azure.com/openai/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "api-key: <API_KEY>" \
  -d '{
    "model": "<DEPLOYMENT_NAME>",
    "messages": [
      {
        "role": "user",
        "content": "What is deep learning?"
      }
    ],
    "chat_template_kwargs": {
      "enable_thinking": true,
      "thinking": true
    }
  }'
```

</hfoption>
<hfoption id="Python SDK">

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://<ACCOUNT_NAME>.services.ai.azure.com/openai/v1",
    api_key="<API_KEY>",
)

response = client.chat.completions.create(
    model="<DEPLOYMENT_NAME>",
    messages=[{"role": "user", "content": "What is deep learning?"}],
    extra_body={
        "chat_template_kwargs": {
            "enable_thinking": True,
            "thinking": True,
        }
    },
)

message = response.choices[0].message
print(getattr(message, "reasoning", None))
print(message.content)
```

</hfoption>
</hfoptions>

When a reasoning parser is configured for the deployment, current vLLM versions return the separated trace in `message.reasoning` and the final answer in `message.content`. Older runtime versions may use `reasoning_content` instead.

### SGLang

Set `separate_reasoning` to `true` to return the trace separately from the final answer.

<hfoptions id="sglang-client">
<hfoption id="cURL">

```bash
curl -sS -X POST \
  "https://<ACCOUNT_NAME>.services.ai.azure.com/openai/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "api-key: <API_KEY>" \
  -d '{
    "model": "<DEPLOYMENT_NAME>",
    "messages": [
      {
        "role": "user",
        "content": "What is deep learning?"
      }
    ],
    "chat_template_kwargs": {
      "enable_thinking": true,
      "thinking": true
    },
    "separate_reasoning": true
  }'
```

</hfoption>
<hfoption id="Python SDK">

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://<ACCOUNT_NAME>.services.ai.azure.com/openai/v1",
    api_key="<API_KEY>",
)

response = client.chat.completions.create(
    model="<DEPLOYMENT_NAME>",
    messages=[{"role": "user", "content": "What is deep learning?"}],
    extra_body={
        "chat_template_kwargs": {
            "enable_thinking": True,
            "thinking": True,

    },

print(getattr(message, "reasoning_content", None))
print(message.content)
```

SGLang returns the separated trace in `message.reasoning_content` and the final answer in `message.content`.

## Responses API

For deployments that expose the Responses API, send requests to `/openai/v1/responses` and use `reasoning.effort`. Supported effort levels vary by model and runtime; `high` enables more reasoning, while `none` requests a direct answer where that level is supported.

<hfoptions id="responses-client">
<hfoption id="cURL">

```bash
curl -sS -X POST \
  "https://<ACCOUNT_NAME>.services.ai.azure.com/openai/v1/responses" \
  -H "Content-Type: application/json" \
  -H "api-key: <API_KEY>" \
  -d '{
    "model": "<DEPLOYMENT_NAME>",
    "input": "Build a small FastAPI health-check endpoint.",
    "reasoning": {
      "effort": "high"
    }
  }'
```

</hfoption>
<hfoption id="Python SDK">

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://<ACCOUNT_NAME>.services.ai.azure.com/openai/v1",
    api_key="<API_KEY>",
)

response = client.responses.create(
    model="<DEPLOYMENT_NAME>",
    input="Build a small FastAPI health-check endpoint.",
    reasoning={"effort": "high"},
)

print(response.output_text)
```

</hfoption>
</hfoptions>

## Models without a switch

Reasoning-only models ignore requests to disable reasoning, while non-reasoning models ignore reasoning controls. Use the model page as the source of truth for supported modes and parameter names.
